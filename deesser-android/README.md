# 刺さりを抑えるソフト（Android 用ディエッサー）

Android 端末で再生される音の「サ行」の歯擦音や耳に刺さる高域だけを、大きくなった瞬間に抑えるアプリです。
操作系は Techivation T-De-Esser 2 を参考にしています（コードや音声処理は独自実装で、同製品とは無関係です）。

## 機能

女性ボーカルの「さ行」、ハイハットの刺さり、歪みギターの耳障りな高音など、**耳に刺さる音が出た瞬間だけ、その周波数だけ**を下げることを目的にしています。

### ターゲット（3種類、それぞれ個別に ON/OFF・調整）

| ターゲット | 初期の帯域 | 反応 | 狙う音 |
|---|---|---|---|
| 歪みギター | 2.5〜5 kHz | ゆっくり（アタック 4 ms / リリース 120 ms） | 持続する「ジャリジャリ」した成分 |
| さ行 | 5〜10 kHz | 速い（1 ms / 60 ms） | ボーカルの歯擦音 |
| ハイハット | 8〜16 kHz | 速い（0.7 ms / 45 ms） | シンバル類の「チッ」「シャーン」 |

各ターゲットのノブ：LOW / HIGH（帯域）、PROCESSING（反応しやすさ）、INTENSITY（下げる強さ）。
共通のノブ：SHARPNESS（ニー幅と反応速度。上記の時間を ×2〜×0.5）、MIX（全体の効き具合）、OUTPUT（出力音量）。

### ピンポイントにする仕組み

- 1.6〜16 kHz を細い帯域（標準 **1/3 オクターブ × 10 本**、細かい **1/6 オクターブ × 20 本**）に分け、帯域ごとに独立したコンプレッサーで検出・抑制します。刺さった帯域だけが下がり、隣の帯域には触れません。
- しきい値は「その帯域の普段のレベル ＋ N dB」で決めます（PROCESSING 0% = +30 dB、50% = +10 dB、100% = −10 dB）。
- 普段のレベルは、オートがオフなら一般的な音楽の周波数バランス（ピンクノイズ＋高域で約 −3 dB/oct）からの推定値、オートがオンなら再生中の音から学習した値（約 10 秒で追従、推定値から ±12 dB の範囲に制限）です。
- 高い帯域ほど反応を速くしています（4 kHz を基準に 2 kHz で ×1.4、16 kHz で ×0.5）。

### オート（再生中の音に追従）

Android の Visualizer で出力音を測ります（8 ビットの波形から周波数バランス、別の計測で全体の音量）。Visualizer はマイクを使いませんが、Android の仕様で「録音」の権限が必要で、バックグラウンドで使うためにサービスを「マイク」種別でも動かしています。端末の再起動直後など、Android がその種別を許可しない場面では、アプリを開くまでオートは止まり、固定の推定値で動作します。
- 周波数の計算には、再生先の出力のサンプリングレートを使います（2 秒ごとに取り直すので、ハイレゾ設定やヘッドホン／Bluetooth の切り替えに追従します）。Visualizer が報告するレートは機種によって正しくないためです（NW-WM1AM2 では実際は 192 kHz／48 kHz なのに 44.1 kHz と報告されます）。現在のレートは画面の「状態」に表示されます。
- ターゲット同士の帯域が重なった部分は、反応しやすい（PROCESSING が高い）方の設定が使われます。

### その他

- Filter モニター：選択中のターゲットの帯域だけを聴く（刺さる帯域を探すため）
- 高域シェルフ（常時）、プリセット、端末起動時の自動開始、プレーヤーの「イコライザー」メニューからの起動
- 「説明文を表示」スイッチ（画面上部）：オフにすると各項目の説明文を隠します（設定は保存されます）

### 動作を止めるには

- 右上の ON をオフ、または通知の「停止」：エフェクトを外し、計測とサービスを止めます。
- 最近使ったアプリの一覧からこのアプリを消す：ON のままでも、エフェクトを外し、計測・通知・サービスをすべて止めます（出力に効果は残りません）。ON の状態は覚えているので、次にアプリを開くと再開します。
- ホームボタンや戻るボタンでほかのアプリに移ったときは止まりません（YouTube Music などで聴いている間も効かせるため）。

T-De-Esser 2 の Processing / Intensity / Sharpness / Mix / Filter モニターの考え方を引き継いでいます。

## 参考にした有料プラグインと、このアプリでの扱い

Android 標準の `DynamicsProcessing`（マルチバンド・コンプレッサー）の範囲で再現できるものを取り入れています。

| プラグイン | 参考にした考え方 | このアプリ |
|---|---|---|
| FabFilter Pro-DS | 全体ミックスには Allround＋Split Band（高域だけ下げる）が向く／Range（最大リダクション） | 高域だけを帯域ごとに下げる方式／INTENSITY を「約 −X dB」で表示（上限を固定する機能は API にないため目安） |
| oeksound soothe2 | 周りより突出した成分だけを狭く削る／Sharpness（削る幅）／高い周波数ほど速く反応 | 細い帯域ごとに検出／1/6 オクターブ（20 帯域）を選択可／高い帯域ほどアタック・リリースを短く |
| Sonnox SuprEsser | Auto Level Tracking（入力レベルにしきい値が追従） | オート：再生中の音量と帯域バランスを測ってしきい値を追従 |
| iZotope RX De-ess（Spectral） | 多数の帯域に分けて、歯擦音のある高域だけを処理 | 同上（帯域数は 10 または 20） |
| T-De-Esser 2 | Processing / Intensity / Sharpness / Mix、Filter モニター | 同名のノブとして継承 |

再現できないもの（`DynamicsProcessing` に該当する機能がない、または元の音を取り出せないため）：

- 先読み（Pro-DS、Waves Sibilance の Lookahead）
- 削った成分だけを聴く Delta / Diff モニター（soothe2、T-De-Esser 2）
- 声の音素を見分ける検出（Pro-DS の Single Vocal、Waves Sibilance、sonible smart:deess の AI 検出）。これらは単体のボーカル向けでもあります
- ステレオリンク・Mid/Side 処理
- 実際のゲインリダクション量の表示

## 仕組み

Android 9 以降に標準で入っている `DynamicsProcessing` エフェクトを使っています。

```
入力 → Pre-EQ（高域シェルフ） → MBC 12バンド [〜1.6k | 1/3oct × 10 | 16k〜] → Post-EQ（Filter モニター・出力ゲイン） → 出力
```

パラメータの換算は `app/src/main/java/app/deesstamer/DspMapping.kt` にまとめてあり、JVM のユニットテストがあります。

### 適用先（どちらか一方）

- **端末全体（グローバル出力）**：オーディオセッション 0 にエフェクトを付け、全アプリの音にかけます。Android のドキュメントではこの使い方は非推奨とされていて、機種によっては付けられない・付いても効かないことがあります。
- **対応プレーヤーごと**：再生時にオーディオセッションを通知するプレーヤー（イコライザー連携に対応したアプリ）にだけかけます。このアプリより先に再生を始めていた場合は、プレーヤー側で一度停止→再生してください。プレーヤーの「イコライザー」メニューからこのアプリを選んでも有効になります。

両方に同時にかけると同じ音が二重に処理されるため、どちらか一方だけを選ぶ仕様にしています。

## インストール

1. `SasariOsaeru-1.3.0.apk` を端末にコピーするか、ダウンロードします。
2. ファイルを開き、「提供元不明のアプリ」のインストールを許可してインストールします。
3. アプリを開いて右上の ON を入れます（Android 13 以降は通知の許可を求められます。許可しなくても動作はします）。

対応 OS：Android 9（API 28）以降。

## 制限

- **Diff モニターは実装していません。** `DynamicsProcessing` では処理前の音を取り出せないため、「削られた成分だけを聴く」ことができません。
- **Mix は近似です。** 本来の Mix は処理前と処理後の音を混ぜるものですが、同じ理由でリダクション量を縮める方式にしています。
- **オートがオフのとき「普段のレベル」は固定の推定値です。** 曲の音作りや端末の音量設定によって効き方が変わる可能性があります。オートを使うか、PROCESSING で調整してください。
- **オートの計測は粗めです。** Visualizer の波形は 8 ビットなので、小さな高域成分は正確に測れません。また計測は処理後の音を見ている可能性があります（その場合も、しきい値が下がり続けることはない設計です）。
- **リダクションメーターはありません。** `DynamicsProcessing` は実際のゲインリダクション量を返さないためです。画面のカーブは設定値から計算した理論上の特性です。
- **オーバーサンプリングはありません**（処理は端末のエフェクトエンジン内で行われます）。
- 同じ種類のエフェクトを使う他のイコライザーアプリ（Wavelet など）とは同時に使わないでください。同じセッションに付けたエフェクトは設定を奪い合います。
- メーカー独自の音響効果や再生経路によっては効かない場合があります。
- APK はデバッグ鍵で署名しています。ビルドした環境が違う APK で上書きインストールすると署名が合わず失敗するので、その場合は一度アンインストールしてください。

## テスト

- JVM ユニットテスト（パラメータ換算・帯域レイアウト・オート計測の解析部）：`./gradlew testDebugUnitTest`
- 端末／エミュレーター上のテスト（`app/src/androidTest`）：`./gradlew connectedDebugAndroidTest`
  - DynamicsProcessing が使えること、12/22 帯域の両レイアウトで作成でき値が反映されること
  - 対応プレーヤーごと方式で、大きな 7 kHz の音が下がり 500 Hz は変わらないこと
  - 初期設定で、小さな高域は触らず大きな高域だけ下がること
  - 何も抑えない設定では音量・音色が変わらないこと
  - サービスが全体（セッション 0）に付き、オート計測が動き、帯域数の切り替えでエフェクトが作り直されること
  - メイン画面が開くこと

  Android 11（API 30、NW-WM1AM2 と同じバージョン）のエミュレーターで全件成功を確認済み。ただし端末全体（セッション 0）方式で実際に音が変わるかは、エミュレーターでは処理後の音を測れないため未確認です。

## ビルド

JDK 17 以上と Android SDK（Platform 35）が必要です。

```sh
cd deesser-android
./gradlew testDebugUnitTest assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

GitHub に push すると `.github/workflows/deesser-android.yml` が APK をビルドし、Actions の成果物（Artifacts）として保存します。
